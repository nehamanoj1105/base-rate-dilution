# GatedSAGE Architecture & Role of Learned Components

Because the hard feasibility gate restricts the candidate set strictly to invariant-violating edges ($\text{mask}(e) = 1.0$), the learned GNN (GraphSAGE) cannot expand detector recall beyond the HARD rule set. Its role is strictly to classify violations WITHIN the candidate set — distinguishing benign invariant violations (caused by OS audit artifacts such as pre-audit daemons, log rotation, daemon reparenting, or clock skew) from true adversarial tampering. Soft-invariant violation indicators ($v_{\text{soft}}$, 4 dimensions) are included as edge features to provide domain signals on non-fatal violations, while hard-invariant indicators ($v_{\text{hard}}$, 11 dimensions) are strictly excluded from feature construction to prevent the neural network from memorizing the feasibility mask rather than learning the benign versus adversarial distinction.
